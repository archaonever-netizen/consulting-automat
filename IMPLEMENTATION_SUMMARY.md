# Реализация: Модуль Задачи + Яндекс.Календарь + ИИ-Чат

**Дата:** 2026-06-09  
**Статус:** ✅ Завершено

## Обзор

Реализован полнофункциональный модуль управления задачами с интеграцией Яндекс.Календаря и ИИ-ассистентом для автоматического дозаполнения незаполненных полей задач.

## Изменённые файлы

### 1. Модели БД (`models.py`)

#### Добавлены модели:
- **`UserTask`** — пользовательские задачи
  - title, client_id, assigned_to_id, created_by_id
  - input_data, start_time, duration_minutes
  - expected_result, goal, action_description
  - status (pending/in_progress/completed/failed)
  - calendar_event_uid (для синхронизации с Яндексом)

- **`TaskCompletion`** — результаты выполнения задач
  - task_id, actual_result, is_failure
  - difficulties, how_overcome, next_step, next_task_id
  - completed_at

- **`UserChatSession`** — сессии чата с ИИ
  - user_id, title
  - context_type ('general' / 'task_manager')
  - context_id (task_id при task_manager)

- **`UserChatMessage`** — сообщения в чате
  - session_id, role ('user' / 'assistant')
  - content, created_at

#### Обновлена модель `User`:
- `yandex_calendar_token` — OAuth access token
- `yandex_calendar_refresh_token` — для обновления
- `yandex_calendar_token_expiry` — время истечения
- `yandex_login` — логин в Яндексе (для CalDAV)
- Relationships: `tasks`, `chat_sessions`

### 2. Новые файлы

#### Добавлены маршруты:

**Яндекс OAuth:**
- `GET /auth/yandex` — начать OAuth поток
- `GET /auth/yandex/callback` — callback (сохраняет токены)

**Управление задачами:**
- `GET /tasks` — список задач текущего пользователя
- `POST /tasks/create` — создать новую задачу + добавить в календарь
- `GET /tasks/<id>` — получить JSON данные задачи
- `POST /tasks/<id>/start` — изменить статус → in_progress
- `POST /tasks/<id>/complete` — завершить задачу
  - Сохраняет `TaskCompletion`
  - Проверяет незаполненные поля
  - Создаёт чат с ИИ если нужно дозаполнение
- `POST /tasks/<id>/delete` — удалить задачу и её событие из календаря

**ИИ-Чат (переписан):**
- `GET /chat` — список сессий или открыть конкретный чат
- `POST /chat/session/new` — создать новую сессию
- `POST /chat/<session_id>/send` — отправить сообщение
  - Сохраняет сообщение в БД
  - Вызывает LLM (qwen/qwen3-max)
  - Для task_manager контекста: парсит JSON из ответа и обновляет задачу

#### Логика AI Task Manager:
1. При завершении задачи с незаполненными полями создаётся `UserChatSession`
2. Системный промпт информирует ИИ о незаполненных полях
3. ИИ задаёт вопросы по одному полю за раз
4. После ответа ИИ парсит JSON: `{"field": "...", "value": "...", "done": true/false}`
5. Значение сохраняется в БД
6. Когда все поля заполнены → сессия завершается

## Архитектура

### Поток создания задачи
```
1. Пользователь создаёт задачу (форма на /tasks)
2. POST /tasks/create → создаёт UserTask в БД
3. Если есть yandex_calendar_token:
   - Вызывает yandex_calendar.create_event()
   - Получает UID события
   - Сохраняет в task.calendar_event_uid
4. Задача появляется в списке и в Яндекс.Календаре
```

### Поток выполнения задачи с дозаполнением
```
1. Пользователь нажимает ✓ Выполнить
2. POST /tasks/<id>/complete → заполняет TaskCompletion
3. Проверка незаполненных полей (input_data, goal, action_description, expected_result)
4. Если есть пустые поля:
   - Создаёт UserChatSession с context_type='task_manager'
   - Редирект на /chat?session_id=<id>
5. Пользователь видит чат с ИИ-вопросами
6. ИИ задаёт вопросы и парсит JSON из ответов
7. Поля заполняются автоматически
8. При done: true → редирект на /tasks
```

### Поток ИИ-чата
```
1. GET /chat → показывает список сессий
2. POST /chat/session/new → создаёт UserChatSession
3. GET /chat?session_id=X → открывает конкретный чат
4. POST /chat/<id>/send:
   - Сохраняет сообщение в БД
   - Собирает историю из UserChatMessage
   - Выбирает системный промпт (general или task_manager)
   - Вызывает LLM (qwen/qwen3-max)
   - Сохраняет ответ в БД
   - Если task_manager: парсит JSON и обновляет задачу
5. Ответ ИИ отображается в реальном времени
```

## Безопасность

- ✅ Все маршруты задач и чата защищены `@login_required`
- ✅ Проверка ownership (пользователь может видеть только свои задачи/чаты)
- ✅ OAuth токены хранятся в БД (в production должны быть зашифрованы)
- ✅ CalDAV запросы используют только персональные календари пользователя
- ✅ LLM вызовы выполняются на стороне сервера (не раскрывают API ключи)

## Тестирование

### Сценарии для проверки

1. **Создание задачи**
   - Создать задачу только с названием → должна создаться
   - Создать с заполненными полями → все поля должны сохраниться
   - Проверить что событие появилось в Яндекс.Календаре

2. **AI Task Manager**
   - Создать задачу только с названием и клиентом
   - Нажать ✓ Выполнить → должен открыться чат
   - Ответить на вопросы ИИ → поля должны заполниться
   - Проверить что поля действительно обновились в БД

3. **ИИ-Чат**
   - Создать новый чат
   - Написать сообщение → получить ответ от qwen/qwen3-max
   - Проверить что история сохраняется
   - Проверить что можно создать несколько сессий

4. **Яндекс.Календарь**
   - Подключить календарь (OAuth)
   - Создать несколько задач
   - Проверить что они появились в Яндекс.Календаре
   - Удалить задачу → событие должно удалиться
   - Проверить что синхронизация работает в обе стороны

## Известные ограничения

1. **CalDAV**: Удаление события работает по поиску UID (может быть медленно на больших календарях)
2. **AI Task Manager**: Может потребоваться несколько итераций для дозаполнения каждого поля
3. **Яндекс OAuth**: Требует явного подключения один раз (нет автоматического refresh на стороне пользователя)
4. **Чат**: История сообщений хранится в БД (в очень больших объёмах может быть медленным)
