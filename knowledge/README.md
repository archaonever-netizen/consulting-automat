# Библиотека источников знаний (`knowledge/`)

Здесь лежат исходные PDF методологий и их «паспорта». Из этой папки источники
загружаются в базу знаний для «умного поиска» ИИ-Методолога.

## Как устроено

Один источник = одна подпапка. Внутри:

```
knowledge/
  cmmi/
    manifest.json        ← «паспорт» источника (вы заполняете)
    CMMI.pdf             ← исходный PDF (первоисточник, не меняется)
    cmmi.fulltext.txt    ← извлечённый текст (создаёт скрипт; в репозиторий)
    cmmi.fragments.jsonl ← куски с привязкой к страницам (создаёт скрипт)
```

`*.fulltext.txt` и `*.fragments.jsonl` **создаёт скрипт автоматически** из PDF —
руками их писать не нужно. PDF хранится как первоисточник (provenance).

## Паспорт источника (`manifest.json`)

| Поле | Что это | Пример |
|---|---|---|
| `key` | короткий стабильный идентификатор (латиницей) | `"cmmi"` |
| `title` | название источника | `"CMMI for Development"` |
| `source_type` | тип источника | `"methodology_framework"` |
| `methodology` | короткий тег методологии | `"CMMI"` |
| `version` | версия | `"2.0"` |
| `language` | язык документа | `"en"` |
| `confidential` | **конфиденциальный?** да/нет | `false` |
| `source_url` | ссылка на оригинал (если есть) | `"https://..."` |
| `pdf_file` | имя PDF внутри этой папки | `"CMMI.pdf"` |
| `notes` | заметки (необязательно) | `""` |

⚠️ **`confidential`** — самое важное поле. Если `true`, источник помечается как
конфиденциальный: его текст **не отправляется** в облако (Promptra) на «умный
поиск». Шаблон — в [`_template/manifest.json`](_template/manifest.json).

## Как загрузить источник (одна команда)

```powershell
.\.venv\Scripts\python.exe scripts\ingest_source.py cmmi
```

Скрипт сам: извлечёт текст из PDF (сохраняя таблицы), разрежет по структуре с
точными страницами, и запишет всё в базу. Повторный запуск **не плодит дубли**
(сравнивает контрольную сумму; перезаписывает только при изменении источника).

> База берётся из `DATABASE_URL`. Чтобы грузить в боевую Supabase, переменная
> должна указывать на неё.

BPMM уже загружен отдельным сидером (`seed_bpmm_source`) и лежит в `BPMM/` —
переносить его сюда не обязательно.
