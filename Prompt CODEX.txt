Ты работаешь в существующем кодовом репозитории приложения. Сначала изучи структуру проекта, компоненты Workspace, раздел Projects / Проекты, существующие модальные окна, навигацию, состояние, стили и паттерны данных. Не переписывай архитектуру с нуля — интегрируй изменение в текущий стиль приложения.

Задача: интегрировать в раздел «Проекты» набор карточек фреймворка целеполагания. Эти карточки должны отображаться как пункты внутри модального окна, которое находится слева от Workspace.

Функциональные требования:

Найди существующий раздел «Проекты» и модальное окно / drawer / sidebar, которое открывается слева от Workspace.
Добавь внутрь раздела «Проекты» список карточек фреймворка целеполагания.
Каждая карточка должна быть отдельным кликабельным пунктом.
При клике карточка должна открывать соответствующий рабочий экран / состояние внутри Workspace или правой рабочей области, в зависимости от текущей архитектуры приложения.
Если в проекте уже есть роутинг, используй существующий роутинг.
Если используется локальный state/store, используй существующий store-подход.
Если для пунктов меню уже есть компонент, переиспользуй его.
Не создавай дублирующие компоненты, если есть существующие UI primitives.
Сохрани визуальный стиль приложения: отступы, типографику, hover, active state, иконки, скругления, цвета.
Активная карточка должна визуально выделяться.
Порядок карточек должен быть фиксированным.
Названия карточек должны быть на русском языке именно в таком виде.
Если в кодовой базе есть i18n, добавь строки через текущий механизм локализации.
Если i18n нет, используй локальные константы.
Добавь типы / интерфейсы, если проект использует TypeScript.
Добавь минимальные тесты, если в проекте уже есть тестовая инфраструктура.
Проверь, что приложение собирается без ошибок линтера и TypeScript.

UI-требования:

Карточки должны отображаться в модальном окне слева от Workspace внутри раздела «Проекты».
Формат карточки: название, короткое описание, возможно иконка или порядковый номер, если это соответствует текущему стилю.
При наведении карточка должна показывать hover-state.
При выборе карточка должна становиться active.
Список должен быть прокручиваемым, если не помещается по высоте.
Интерфейс должен быть адаптивным и не ломать Workspace.
Не меняй существующую бизнес-логику проектов без необходимости.

Поведение при клике:

Если для карточек уже существует экран — свяжи пункт с ним.
Если экранов еще нет, создай базовый placeholder-screen для каждой карточки.
Placeholder должен показывать:
название карточки;
краткое описание;
пустое состояние;
место для будущего контента.
Не реализуй сложные формы на этом этапе, только навигационную структуру и базовые экраны.

Ожидаемый результат:

В левом модальном окне Workspace в разделе «Проекты» появился список из 13 карточек фреймворка.
Карточки кликабельны.
Активная карточка выделяется.
При клике открывается соответствующий экран или placeholder.
Код соответствует текущей архитектуре проекта.
Проект проходит build / lint / typecheck.
В конце кратко опиши, какие файлы были изменены и как проверить результат вручную.


Дополнительное важное требование: в проекте уже есть незакоммиченные изменения. Работай максимально безопасно и не перетирай чужую работу.

Перед внесением изменений:

Проверь текущее состояние репозитория через git status.
Определи, какие файлы уже изменены до начала твоей работы.
Не форматируй весь проект и не запускай автоформатирование на файлах, которые не трогаешь по задаче.
Не делай массовые рефакторинги.
Не изменяй файлы с существующими незакоммиченными изменениями, если можно реализовать задачу через новые файлы или через другие участки кода.
Если нужный файл уже изменен, сначала внимательно посмотри diff и внеси минимальный точечный патч, не удаляя и не переписывая существующие изменения.
Не выполняй git checkout, git reset, git clean, git stash, git restore без явного разрешения.
Не удаляй существующие изменения пользователя.
Старайся добавлять новые компоненты, константы и типы в отдельные новые файлы, если это не противоречит архитектуре проекта.
В финальном отчете отдельно укажи:
какие файлы уже были изменены до начала работы;
какие файлы изменил ты;
были ли затронуты файлы с чужими незакоммиченными изменениями;
как вручную проверить результат.

Если для выполнения задачи невозможно не трогать уже измененный файл, внеси минимально необходимое изменение и явно отметь это в финальном отчете.
