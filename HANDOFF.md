# HANDOFF — «Умный поиск» (RAG) + ИИ-Методолог

Памятка для следующего чата: что построено, ключевые файлы/команды и что отложено.
Подробный журнал решений — в памяти проекта (`MEMORY.md` → `rag-methodolog-decisions`).

## Что построено (готово, 6 фаз)

RAG-поиск и агент-Методолог поверх существующей базы знаний. Источник-пилот — BPMM.

- **Структура БД (Supabase Postgres, прод-проект `bklayrmmgbgowbdihyef`):** включены
  `pgvector` + `pg_trgm`; у фрагментов добавлены метаданные (methodology, content_type,
  lang, confidential, поисковый `search_tsv`); новые таблицы `knowledge_cards`
  (карточки методик / типичные ошибки / диагностические вопросы),
  `knowledge_embeddings` (vector(1536) + HNSW), `knowledge_generation_state`
  (идемпотентность генерации). RLS включён на новых таблицах.
- **Загрузка источников:** папка `knowledge/<key>/` с `manifest.json` («паспорт»,
  в т.ч. флаг `confidential`). Извлечение текста+таблиц из PDF, нарезка по структуре
  с точными страницами, идемпотентная запись в БД (без дублей).
- **Эмбеддинги:** AITunnel (OpenAI-совместимый), модель `text-embedding-3-large`,
  **dimensions=1536** (одна и та же модель+размерность при загрузке и поиске).
  Promptra — ТОЛЬКО чат (эмбеддингов у него нет).
- **Производные слои:** русские карточки/ошибки/вопросы, сгенерированы по BPMM
  (модель `google/gemini-3.1-flash-lite`), 711 карточек. Каждая привязана к реальному
  фрагменту+странице.
- **Гибридный поиск:** смысл (pgvector) + слова (FTS/триграммы) + объединение RRF +
  фильтры (методология, тип) + схлопывание near-дублей.
- **Агент-Методолог:** формат «пересказ → риск/ошибка → методика → ССЫЛКА
  (источник/страница/раздел) → уточняющие вопросы → как правильнее». Жёсткая защита
  от выдуманных ссылок: страницы берутся из найденных данных, не из текста модели.
- **Замер качества (независимый эталон из BPMM.pdf):** старый поиск по словам
  топ-5 = 0/10; новый умный топ-5 = 10/10 (топ-3 = 9/10), MRR 0.78.

## Экран «Добавить методологию» (загрузка PDF без CLI)

Основатель добавляет новый источник через UI (раздел «Знания» → «➕ Добавить
методологию»), без терминала. Кнопка «Добавить» защищена паролем-замком (как
редактирование ботов). Конвейер идёт В ФОНЕ: извлечение → запись → эмбеддинги →
русские карточки → эмбеддинги карточек → `processed` → привязка к кластеру
(=фреймворк). Прогресс/токены показываются в реальном времени; по «Готово» —
потраченные токены и 2–3 примера карточек. Источник сразу доступен ботам кластера.

«Всё-или-ничего» через видимость: источник весь импорт в `processing` и НЕ виден
поиску (поиск показывает только `processed`). При сбое PDF и задача сохраняются,
повтор возобновляется по идемпотентности. «Зависшую» задачу (сервер перезапустился)
экран ловит по отсутствию прогресса и даёт «Отменить/Повторить».

| Файл | Назначение |
|---|---|
| `backend/routes/sources.py` | API: upload(оценка) / run(+замок) / status / cancel / sample-cards |
| `backend/services/source_admin.py` | оценка стоимости, создание/запуск/статус задачи, карточки |
| `backend/services/source_ingest_runner.py` | фоновый оркестратор (дёргает скрипты, токены, откат) |
| `backend/services/storage_client.py` | Supabase Storage (оригиналы PDF) |
| `backend/services/knowledge_ingest.py` → `cleanup_source` | полная уборка источника (отмена/замена) |
| `frontend/src/components/AddMethodologyModal.tsx` | экран (форма→оценка→прогресс→готово) |
| `migrations/add_methodology_ingest_jobs.sql` | таблица ingest_jobs (применено в Supabase) |

ВАЖНО (деплой): `pypdf` и `pdfplumber` теперь в `requirements.txt` (прод) — экран
извлекает PDF на боевом сервере. Storage требует `SUPABASE_URL` + `SUPABASE_SERVICE_KEY`
(`service_role`, только на сервере) в `.env.local`. Фон сейчас — `asyncio.create_task`
в процессе сервера (без Celery); при перезапуске посреди импорта задача «зависает»
(данные не теряются, источник невидим) — экран это обрабатывает.

Бэклог: удаление/замена уже добавленной методологии (переиспользовать `cleanup_source`).

## Команды

База берётся из `DATABASE_URL`. Для прод-операций он должен указывать на Supabase
(строка — в `.env.local`, закомментирована). Ключи (`EMBEDDINGS_*`, `PROMPTRA_*`) — в
`.env.local` (в `.gitignore`, в репозиторий не коммитятся).

```powershell
# Загрузить новый источник (PDF + manifest.json в knowledge/<key>/)
.\.venv\Scripts\python.exe scripts\ingest_source.py <key>
# Посчитать эмбеддинги (фрагменты и/или карточки)
.\.venv\Scripts\python.exe scripts\build_embeddings.py --owner all
# Сгенерировать русские карточки по источнику
.\.venv\Scripts\python.exe scripts\build_layers.py --source <key>
# Демонстрация агента / поиска / замера
.\.venv\Scripts\python.exe scripts\methodolog_demo.py
.\.venv\Scripts\python.exe scripts\eval_search.py
```

> Эмбеддинги/поиск работают только на Postgres (pgvector). Локальная SQLite-лаба их
> не видит — это ожидаемо; RAG живёт в боевой Supabase.

## Отложенные доработки (по согласованию с владельцем)

1. **Русская морфология поиска по словам.** Сейчас FTS на конфиге `simple` не учитывает
   русские окончания («ошибки» ≠ «ошибка»). Семантика вытягивает, но точные термины по
   карточкам ловятся слабо. Решение: отдельный FTS-конфиг `russian` для русских карточек.
2. **Переранжирование (rerank) топа.** Сейчас порядок задаёт RRF — этого хватает.
   При желании добавить шаг до-сортировки (дешёвый эвристический или платный LLM/cross-encoder).
3. **Несовпадение названий разделов в ссылках.** В BPMM соседние пункты оглавления делят
   текст одной страницы, поэтому заголовок раздела в ссылке иногда не точно совпадает с
   содержимым страницы (напр. фрагмент «1.2 Foundation Principles» содержит текст «1.1»).
   Страницы корректны; уточнить можно более тонкой нарезкой внутри страницы.
4. **Конкурентность нескольких ботов к одному API.** Скрипты ходят к Promptra/AITunnel
   с одним ключом. При нескольких параллельных ботах/процессах учесть лимиты скорости,
   ретраи/бэкофф и общий бюджет; при необходимости — очередь или пул ключей.

## Безопасность

- `.env.local` содержит ключи — НЕ коммитить (в `.gitignore`).
- На старых 20 таблицах Supabase отключён RLS — отдельная задача (`docs/SECURITY_RLS_TODO.md`).
- Конфиденциальные источники: флаг `confidential` есть в схеме. Текущее решение владельца —
  облако (AITunnel) допустимо для всех; при изменении политики флаг позволит развести пути.
