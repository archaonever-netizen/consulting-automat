## 🔴 СРОЧНО

Критичных проблем безопасности, требующих немедленных действий, **не обнаружено**.

Проверено отдельно: файл с секретами `.env.local` в git **не попал** (отслеживаются
только безопасные `.env.example` и фронтовые конфиги без секретов).

Найдены две некритичные уязвимости, исправляются в Этапе 4/6:
1. **Path traversal** в раздаче файлов SPA (`backend/main.py`, serve_spa) — злоумышленник
   мог бы запросом вида `/../backend/...` прочитать файлы исходников на сервере.
2. **Нет ограничения частоты запросов** к ИИ-эндпоинтам (чат, декомпозиция) — авторизованный
   пользователь может случайно/намеренно сжечь бюджет LLM-API частыми запросами.

## Карта проекта (Этап 0 — разведка)

**Что это:** веб-приложение для консалтинга «ШЕФ»: клиенты и брифы, структура компании
(функции/отделы), цели с ИИ-декомпозицией, задачи, ИИ-чат, оркестрация сети агентов,
трекер Kaiten, база знаний (BPMM).

**Стек:**
- Бэкенд: Python 3.12, FastAPI, async SQLAlchemy 2.0, LangChain/LangGraph (ИИ-агенты).
- Фронтенд: React 19 + TypeScript, Vite 8 (на Rolldown), react-router 7, axios.
- БД: SQLite (`instance/app.db` локально; на проде — файл на смонтированном диске `/data/app.db`).
- Деплой: Amvera, Docker. **Важно:** собранный фронтенд `frontend/dist` коммитится в репозиторий
  и попадает в Docker-образ как есть. Перед коммитом dist обязан собираться с пустым
  `VITE_API_URL` (относительные адреса API), иначе в прод зашьётся localhost.

**Структура папок:**
| Папка | Назначение |
|---|---|
| `backend/` | FastAPI: `main.py` (вход), `models.py` (22 таблицы), `routes/` (API), `services/` (логика), `core/` (конфиг, БД, шифрование) |
| `backend/services/agent_network/` | сеть ИИ-агентов на LangGraph (см. ARCHITECTURE_AGENTS.md) |
| `backend/services/goal_decomposition/` | фреймворк декомпозиции целей + верификатор + тесты |
| `frontend/src/` | React: `pages/` (16 экранов), `components/` (Layout, виджеты), `services/api.ts` (axios+JWT) |
| `frontend/dist/` | прод-сборка (коммитится!) |
| `BPMM/` | источник базы знаний (PDF + текст + фрагменты для RAG) |
| `decompsition/` | документация фреймворка декомпозиции (промпты, спека) |
| `instance/` | локальная SQLite-БД (в git не попадает) |
| `docs/` | документация (этот журнал, заметки, архитектура) |
| `templates/`, `static/` | ⚰️ мёртвое наследие старого Flask-приложения (удаляется в Этапе 1) |

**Точки входа:**
- Бэкенд: `python -m uvicorn backend.main:app --port 8000` (старт ~9 сек: создание таблиц, сид основателя и базы знаний).
- Фронтенд дев: `npm run dev` в `frontend/` (порт 5173); прод: FastAPI раздаёт `frontend/dist`.
- Авторизация: JWT, логин по email/паролю; основатель сидится из `FOUNDER_EMAIL`/`FOUNDER_PASSWORD`.

**Хранение данных:** всё в одной БД (22 таблицы): пользователи, клиенты, брифы+секции,
функции/отделы и связи, задачи, чат-сессии/сообщения, цели и декомпозиция, база знаний
(категории/статьи/источники/фрагменты), подключение Kaiten (токен шифруется Fernet-ключом,
производным от SECRET_KEY). На фронте в localStorage — только JWT-токен и userId.

### Этап 4 — Производительность и UX (12.06.2026) ✅

Цель: «все переходы тормозят» (со слов владельца). Причины: один JS-файл 560 КБ
без кэширования + полный перезапрос данных на каждый переход. Сделано 9 шагов,
каждый — отдельный коммит с проверками (tsc, vitest, build, grep dist, смоук uvicorn):

| Шаг | Коммит | До → После |
|---|---|---|
| Path traversal fix (безопасность, см. Этап 6) | 8747c5c | дыра → атаки получают index.html |
| Cache-Control на статику | 5e1808b | браузер качал бандл каждый визит → /assets/* кэш на год (immutable), index.html — 304 |
| Vendor-чанк (react/router/axios/react-query) | 95b8cc6, c7779c1 | один файл → стабильный vendor 298 КБ в вечном кэше |
| React.lazy: 3 ИИ-экрана с markdown | d55f504 | react-markdown 115 КБ грузится только при заходе в Чат/Знания/Оркестрацию |
| React.lazy: остальные 11 экранов | 0ece2bc | **стартовый JS 560 → 319 КБ**, экраны по 1–22 КБ по требованию |
| react-query: Tasks | 474053a | повторный вход — мгновенно из кэша (30 с), потом данные сразу + фоновое обновление |
| react-query: Goals, Home | 35695e7 | то же; профиль (ключ `me`) грузится 1 раз на 5 мин |
| react-query: Clients, ClientDetail | 659ecd9 | мутации инвалидируют список+карточку+сводку разом |
| react-query: Company, Knowledge | dc430ca | то же для матрицы и базы знаний |
| Layout через useQuery + clear() на выходе | 2c66081 | белый экран при каждом hard reload → мгновенный каркас |

**Не трогал сознательно:** ChatPage (стриминг SSE), TrackerPage (уже свой кэш с
коммита ff8eac3), GoalDecompositionPage (сложная state-машина) — работают как раньше.

**Поведение для пользователя:** переход между разделами теперь не перезапрашивает
данные (до 30 секунд — мгновенно из кэша; после — старые данные сразу на экране,
обновление в фоне). Код экрана качается один раз и навсегда оседает в кэше браузера.
Hard reload не показывает белый экран. Навигация при докачке кода держит текущую
страницу на экране (React Router оборачивает переходы в startTransition).
