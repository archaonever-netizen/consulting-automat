# Раздел «Программирование» — план интеграции инструмента гипотез

Цель: превратить раздел `programming` (Гипотезы / Проверки / Решения / OKR) из плоского
списка форм в инструмент **планирования, проведения и проверки гипотез** — без поломки
того, что уже работает.

## Принцип безопасности

Новый экран — **надстройка над теми же данными**, а не новая модель. «Карта» и «Конвейер» —
это другой способ показать те же гипотезы/проверки/решения, что сохраняются сегодня.
В любой момент можно вернуться к старому виду; сохранённые данные клиентов не теряются.

## Что заморожено (трогать нельзя)

1. **Идентификаторы карточек** — `hypotheses`, `experiments`, `decisions`, `okr-kpi`.
   На них завязаны граф «Весь проект», методолог и применятель правок.
2. **Имена полей внутри карточки** — новый экран читает и пишет ровно те же поля,
   что нынешняя форма. Иначе уже введённые данные осиротеют.
3. **Путь сохранения** — гипотезы пишутся тем же снапшот-механизмом, что и сейчас.
4. **Связи графа** (`projectCrossRefs`) — только дополняем реестр, ничего не удаляем.
5. **Клиентский портал** — читает композицию раздела; форму данных не ломаем.
